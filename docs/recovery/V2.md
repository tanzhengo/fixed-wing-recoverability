# 第二阶段：候选覆盖与剩余方案复验

本版在第一版有限时域原型上，改善有限候选预算，并增加可执行的剩余方案管理。仍然不含神经网络，也不提供不变安全集或递归可行性证明。第一版数据继续保存在 `results/`，本版单独保存在 `v2/`。

## 1. 给不同机动分配检查机会

第一版按原代价排序取前12个主候选。这些候选可能只是同一方向的小幅变化，尚未检查左右转向就耗尽预算。

新 `candidate_order: diverse` 保留最低代价候选，再按候选终态航向和高度的差异，逐次选择距离已选集合最远的候选。航向使用圆周角差；航向尺度取空速、滚转限值和主段时长对应的名义转向范围，高度尺度取名义可达垂向范围。不会把狭窄高度带里的微小差别归一化成完整垂向范围。

每个候选仍通过显式动力学、包线和碰撞检查。排定集合不是代价顺序，因此从通过者中选最低代价者；若全局最低代价候选直接通过，可以提前结束。调度最大仍为12个主候选，不意味着每次计算完全相同，更不是墙钟时间硬截止。

旧 `cost` 模式保持兼容。仍然计算完整的主基元库；本次节省的是后续验证工作，尚未减少主候选生成开销。

## 2. 重新验证并执行已有方案的剩余部分

新一轮无法找到证据时，旧实现会降级到仅当前主段可行的控制。启用 `reuse_verified_plan` 后，保留上次实际接受的主段与后续段控制序列，并按已经执行的时间扣减。

再次使用前，从最新实际状态逐段重新积分，检查全部剩余轨迹的飞行包线、障碍和已知区域；动态障碍时间从当前快照起累计。只有重验通过才返回 `REVALIDATED_PLAN`，并以 `reused_verified_plan=true` 标记。它与新产生的 `RECOVERY_VERIFIED` 分开统计。

重验失败、时间非法、方案耗尽、外部替换控制或首段剩余时间不足，都不能继续沿用旧证据。首段需覆盖 `min_execution_time`；线上默认为0.1秒，离线实验使用0.2秒。这个配置不是实际控制延迟上界，超周期、状态反馈延迟和动力学误差仍需独立研究。

将上一控制重新加入新候选库时，必须按完整主段时域重新展开；不能把缓存短尾重新包装成新的3秒主轨迹。复用分支保留本周期已扣费的时间起点，使计算耗时在下一周期计入旧方案余量；这只是时长记账，不是执行延迟补偿。

剩余方案越用越短。即使重验成功，也不代表存在新的固定长度后续轨迹，更不代表能无限续飞。无新证据且无可复用方案时，仍明确记录降级/无解；不会声称固定翼能够安全原地停止。

## 3. 实验协议

预先固定原4个场景，再加入2个诊断场景：原死胡同整体后移30米以检查入口机动余量，以及另一组错列柱体。新场景是开发诊断，不是统计独立的泛化测试集；失败不删除。

- 主矩阵：6场景 × 3初始横向偏移 × 9方法 = 162回合，每种方法18回合。
- 额外扰动设置：2个新增场景 × 2空速（14/17 m/s）× 2理想已知半径（0/120 m）× 4种6秒后续策略 = 32回合。
- 合计194回合。额外32回合单独统计，不和主矩阵混合比较成功率。
- 相同输入测试：54个场景—物理状态 × 2后续时域 × 3排序策略 × 3次轮换顺序计时 = 972次测量，即108组输入。三个计时重复不当作独立样本。

相同输入测试匹配完整状态、地图、目标和上一控制，使用完整代价顺序搜索作为**有限基元库参照**。它不是物理可恢复性真值。检查有限预算找到证据而参照没找到、成本小于完整参照、重复决策不一致等矛盾。缓存方案有路径历史，因此不混入这个无缓存排序比较。

后续时长从3秒变为6秒会同时改变目标距离、控制增益和候选轨迹，并非简单将原3秒轨迹向后延长。三种恢复策略使用相同包线约束；原 `baseline/long6` 保留旧阈值，因此与它们的差异不仅包含终端检查，还包含包线硬过滤。

所有被控对象仍与规划共享同一模型，控制周期0.2秒，不模拟计算期间继续飞行。常规15.5 m/s回合保留上一版初态以便核对；14/17 m/s回合和相同输入测试按各自空速求解该模型的平飞配平。全局几何已知，120米球仅是理想观测范围，不包含FOV或遮挡。

## 4. 编译、测试与运行

在catkin工作区根目录：

```bash
source /opt/ros/noetic/setup.bash
catkin_make -j2 -DCATKIN_WHITELIST_PACKAGES="motion_primitives_planning;simple_airplane_plugins;simple_airplane_gazebo;simple_airplane_description"
source devel/setup.bash
catkin_make motion_primitives_3d_test terminal_recovery_test -j2
rostest motion_primitives_planning motion_primitives_3d.test
rostest motion_primitives_planning terminal_recovery.test
roslaunch motion_primitives_planning terminal_recovery_v2.launch paused:=false
```

新入口默认使用12候选、多方向调度和6秒后续。剩余方案复验用 `reuse_verified_plan:=true` 单独开启：它在主矩阵有收益，但额外速度/观测范围测试存在退化，因此暂不默认启用。原 `terminal_recovery.launch` 保留原默认设置用于比较。无界面检查加 `gui:=false rviz:=false`。

```bash
mkdir -p results
roslaunch -p 11331 motion_primitives_planning recovery_benchmark_v2.launch output_prefix:=$PWD/results/recovery_v2
rosrun motion_primitives_planning analyze_recovery_v2.py $PWD/results/recovery_v2
rosrun motion_primitives_planning plot_recovery_v2.py $PWD/results/recovery_v2
```

`planning_status` 增加调度数量、选中候选的代价排名、主段/后续/缓存的积分步数与剩余方案时长。统计平均耗时时应保留失败回合；方法间轨迹不同，混合状态的平均耗时不能当作同工作量的加速比。
