# Reconstruction development context

This file applies to `reconstruction/`. Read `README.txt` and `UBUNTU_GUIDE.md` before changing this implementation; read `ros/INTEGRATION_CONTRACT.txt` before ROS integration. The user's current request takes precedence over this context.

- This is newly reconstructed Python/NumPy code, not recovered historical source. The specification was the user-supplied LaTeX `main11.tex`, not the archived repository `paper/main.tex`. The current LaTeX project is not bundled here; locate it before manuscript edits.
- Preserve the documented 58-feature schema, H=B=3 s, K=12, candidate order and explicit validation semantics unless a change has a stated technical basis. Keep historical C++/ROS code, models and experiment records identifiable as historical.
- Planning and feature encoding may use only observed-map snapshots. Scene truth belongs only to the sensor simulator and independent evaluator. Invalid/missing rays do not establish free space.
- A proposed path is not an executable command until dispatch validation accepts it. Use actual issued-command timestamps and complete command history. Rejection does not imply a fixed-wing vehicle can stop.
- Use a project virtual environment with Python 3.10+. From this directory run `python scripts/run_checks.py --output runs/<new-run>/software_checks.json` after relevant code changes. The initial release had 76 passing checks on Windows; Ubuntu has not yet been verified in the published baseline. Add meaningful regression coverage for fixes; never suppress a failure to match the prior count.
- Follow the actual CLI interfaces in `scripts/`. `label_dataset.py` requires JSONL frames and `.npz` output. `replay_query.py` requires one JSON frame. Learned modes require an explicitly trained checkpoint; reject archived incompatible weights.
- Put new records in a fresh `runs/` subdirectory. Keep source/config/input/model hashes, resolved dependencies, all failures and actual outcomes. Preserve the original `validation/software_checks.json`; record new environments separately.
- Constructed map diagnostics and synchronous zero-computation-latency episodes are not flight data, historical reproduction, asynchronous validation, or proof of recursive safety. Never manufacture evidence, rename a smoke model to historical `Selected`, or silently replace paper tables.
- The ROS adapter and real-time integration are pending work. Existing launch files run the historical planner. Implement and verify the new path in a distinct package/target before claiming integration.
- Inspect Git status before edits and preserve unrelated work. Review code and documentation diffs before committing. Push only within the user's authorized branch workflow; do not merge main or add large generated records/weights by default.
